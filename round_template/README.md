# round_template · 审批台的唯一模板（v3.7.1）

一轮审批台 = 这一轮的**数据**（`data_rXX.js`）+ **配置**（`cfg_rXX.json`）+ 项目的**代号表**（`codes.js`），由 `build.py` 拼成页面。模板里不含任何具体项目的文字、路径或约定；项目相关的内容都写在 cfg 和数据里。唯一的默认值是 skill 自己的约定：反馈落盘的评审文件夹不写时按 `interview/reviews`（cfg 的 `REVIEW_DIR` 可改，构建时会提示）。

`<skill>` 指本 skill 所在的文件夹（例如项目里固定版本的副本 `skills/interactive-approval-desk/`）。模板和公用模块不需要复制到项目里。`sample/` 里有两轮可以直接构建的示例：R01 是第一轮，用到沙盘、议程、完成条件、关键几件事、来源、名词、全部五种卡片，以及 v3.7 的低负担写法（页面速览、简报四格、七种图、参考表、对象写法的选项、对照式的点；R01-03、R01-05 故意保留旧写法）；R02 是没有沙盘的第二轮（用 `NO_SANDBOX` 写明为什么），带“上一轮处理”和 `changed`，其余故意整轮保留 v3.6 的写法，用来对照两种写法和检查旧数据照样能构建。

## 做一轮的步骤

在放 cfg 和数据的文件夹里（例如 `interview/reviews/build/`）：

```bash
python3 <skill>/scripts/build_codes.py --out codes.js [--shapes code_shapes.json] <登记文件.md …>   # 权威的文件放前面
python3 <skill>/round_template/build.py cfg_rXX.json                     # 输出 {ROUND}_{TOPIC}_proposal.html 和 _artifact.html
NODE_PATH=<装有 playwright 的 node_modules> node <skill>/round_template/test.js RXX        # 自检；不通过时退出码为 1
NODE_PATH=<装有 playwright 的 node_modules> node <skill>/round_template/dumptext.js out.txt RXX   # 冷读材料：先是默认看到的，再是全部展开的
```

- `{ROUND}_{TOPIC}_proposal.html`：完整的 HTML 文档，是本地副本（放进评审文件夹）。
- `{ROUND}_{TOPIC}_artifact.html`：同一页面去掉 doctype/html/head/body，用 Artifact 工具发布它，声明 `capabilities: {db: {}, downloads: true}`。托管页面上：打开时先读数据库里的草稿 `drafts/{ROUND}`（读的那一两秒不能作答），之后每次表态自动存草稿，换台设备打开同一个链接能接着答；新旧按修订号判断，不看设备时钟；别的窗口或设备存过更新的草稿时不覆盖，提示刷新；草稿和本页的存储键绑定，`KEY` 升级后旧草稿不再使用；第三个按钮变成“💾 另存一份 md 到本机”（用 `downloads` 能力，查看者确认后才保存，这个能力不可用时不显示）；数据库连不上或写入失败时提示“没有提交成功”，并选中 Markdown 预览请审批者复制。
- `build.py` 会提示：cfg 里 v3.7 不认识的字段（多半是 v3.4 时项目自己加的，见文末升级对照）、没写 `REVIEW_DIR`、数据里的 `PROPOSAL_FILE` 和输出文件名不一致。cfg 与数据的 `ROUND`、`TOPIC` 不一致时直接报错。
- `test.js` 检查：沙盘每个视图零重叠、零越界；没有未解释的代号，每个代号都进了代号索引；没有重复的元素 id；“一键通过”批量通过的条目在卡片和导出里都标出“全页一键通过”；存储键带 `PROJECT` 前缀；托管模式（表态后存草稿、提交写进 `feedback/{ROUND}`、另存走 `downloads`、接着数据库里更新的草稿、连不上数据库时如实提示且不下载）；本地文件夹（只写一个 md）和下载兜底（恰好一个 md）；手机宽度不横向溢出；没有页面错误。v3.7 起还查：数据检查（`window.__lint()`：形状、诚实、数字出处；它的提示也打印出来，不影响通过）、每张卡默认看到的字数和预算（打印一张表）、读得清（字不小于 12px，浅色和深色下对比度不低于 4.5:1）、推荐的选项不加重、没表态的点都显示“待你表态”、点选项的补充或“原文”不会误选这个选项、折叠按钮的键不重复、`bulk: false` 的分组一键通过不填、有简报和图的卡反馈 md 里有对应的行、375px 和 360px 宽时折叠全开卡片和图表也不溢出。v3.7.1 起还查：沙盘每个视图都画得出来，方框和标签不跑出画布，标签的字不比标签宽；审批路线在条目一节的开头、卡片之前；没有沙盘时“从零看懂”第 2 步一定写“这一轮没有沙盘”（打印出来），写了 `NO_SANDBOX` 就要显示这句。给轮次号时，同一轮有多个页面就取修改时间最新的，并列出没有检查的。截图写在当前文件夹（`shot_*.png`）。

## cfg 字段

相对路径都相对 cfg 文件所在的文件夹，输出也写在那里。

| 字段 | 必填 | 作用 | 省略时 |
|---|---|---|---|
| `PROJECT` | 是 | 项目标识，只用字母、数字、`_`、`-`，最长 24 个字符（如 `weekly_report_demo`）。加在浏览器存储键前面：本地打开的页面在浏览器里共用一份存储，不加的话不同项目的同一轮会串答案 | — |
| `ROUND` | 是 | 轮次，如 `R03`；必须和数据里的 `ROUND` 一致；只能用字母、数字和 `_ . ~ : @ + -`（它会出现在数据库路径 `feedback/{ROUND}`、`drafts/{ROUND}` 里） | — |
| `TOPIC` | 是 | 主题，用在文件名和页面上；必须和数据里的 `TOPIC` 一致；不能含 `/` `\` | — |
| `data` | 是 | 数据文件；也可以是数组，按顺序拼接，例如 `["project.js", "data_r03.js"]`（每轮相同的设置放在前一个文件里） | — |
| `codes` | 否 | 代号表文件（`build_codes.py` 的输出，或项目自己脚本的输出） | `codes.js`；文件不存在时代号表为空，并给出提示 |
| `PAGE_TITLE` | 否 | 浏览器标签页标题 | `{ROUND} · {TOPIC} · 审批台` |
| `HEADER` | 否 | 页眉标题（后面自动加“ · 审批台”） | `TOPIC` |
| `INTRO` | 否 | 导语开头介绍项目的一句（HTML），每轮都一样时写这里 | 空 |
| `LEAD` | 否 | 本轮导语（HTML；导语是 `<div>`，可以用 `<p>` 分段） | 空 |
| `REVIEW_DIR` | 否 | 反馈落盘的评审文件夹（项目内的相对路径，如 `plan/reviews`）；用在提交说明、反馈 md 和导出提示里。`""` 或 `"."` 表示项目根目录 | `interview/reviews`（skill 的约定），构建时提示 |
| `REVIEW_PATH_HINT` | 否 | 本地模式第一次选文件夹时给的路径提示（如 `my_project/interview/reviews`） | 同 `REVIEW_DIR` |
| `TP`、`TF` | 否 | 提案、反馈对应的对话轮次；数据里有 `TURN_PROPOSAL` / `TURN_FEEDBACK` 时以数据为准 | 不显示 |
| `AGENDA_TITLE`、`TCOND_TITLE` | 否 | “议程”“完成条件”两块的标题 | `议程：本轮处理的议题`、`什么时候算完成` |
| `LEGEND_CHIPS` | 否 | 图例里列出的卡片类型，`[[样式, 文字], …]` | 按本页用到的卡片类型自动生成 |
| `PAGE_TEXT` | 否 | 按元素 id 改写标题和说明（见下），适合放项目级的写法 | — |
| `BUDGET` | 否 | `"fail"` 或 `"warn"`：字数超预算、字小于 12px、对比度不够、375 / 360px 溢出时，以及（v3.7.1）沙盘的方框或标签跑出画布、标签的字比标签宽时，`test.js` 是不通过还是只提示。`"warn"` 只用于重建以前的旧轮次，构建时会提示 | `"fail"` |
| `ROUTE` | 否 | 写 `false` 时不显示“审批路线”。v3.7.1 起它在 STEP 3（逐条表态）的开头、卡片之前，“→ 下一个待表态”在它的标题行，超过 8 张卡时其余的收起（“📖 展开全部说明”也会展开）；v3.7 放在 STEP 0，会把沙盘往下推 | 显示（两张卡以上） |
| `CSS_FILE`、`CSS` | 否 | 本项目补充的样式（文件 / 字符串），放在模板样式之后 | — |
| `template`、`linker`、`export` | 否 | 改用别的模板、代号链接器、导出模块 | 本 skill 自带的 |
| `out_proposal`、`out_artifact` | 否 | 输出文件名（反馈里写的提案文件名跟着 `out_proposal` 走） | `{ROUND}_{TOPIC}_proposal.html`、`{ROUND}_{TOPIC}_artifact.html` |

v3.4 cfg 里的 `N`（条目数）不再需要，页面按 `ITEMS` 计数。

## 数据契约（数据文件里的全局量）

必需的只有 `ROUND`、`TOPIC`、`ITEMS`。其余都可以省略，省略时对应的模块不显示。数据和模板在同一个 `<script>` 里，数据不要声明模板已经用的顶层名字（`AD_` 开头的、`HAS_SB`、`adShow`，以及模板的函数名）。

| 全局量 | 形状 | 省略时 |
|---|---|---|
| `ROUND`、`TOPIC` | 字符串 | 必填 |
| `ITEMS` | 条目数组，见下一节 | 必填 |
| `KEY` | 浏览器本地存储键；页面实际存在 `{PROJECT}/{KEY}` 下 | `` `${ROUND}-feedback-v1` `` |
| `PROPOSAL_FILE` | 反馈 md 里写的提案文件名 | 输出文件名（`{ROUND}_{TOPIC}_proposal.html` 或 cfg 的 `out_proposal`） |
| `TURN_PROPOSAL`、`TURN_FEEDBACK` | 对话轮次；声明了就照原样写进反馈 md 的轮次行 | 用 cfg 的 `TP` / `TF`；都没有就不写这一行 |
| `TERMS` | `{词: [解释, 例子]}`；条目里第一次出现的词自动加悬浮解释 | 不显示名词解释 |
| `TERMS_NOAUTO` | `[词, …]`：在本页有别的意思、不要自动加悬浮的词 | — |
| `SOURCES` | `{编号: [标题, 说明, 网址]}` | 不显示来源 |
| `SRC_AUTO` | `[来源编号, …]`：条目正文（`plain`、`evidence`、`context`）里出现就自动链接到来源；只认 `SOURCES` 里有的，已有的链接和 HTML 标签里的文字不动 | 不自动链接 |
| `AGENDA` | `[[编号, 名称, 状态], …]`，状态是 `now` / `part` / `done` / 空 | 不显示议程 |
| `TCOND` | `[[编号, 名称, 说明], …]`：这个评审什么时候算完成 | 不显示完成条件 |
| `DELTAS` | `[[标题, 说明, 条目 id], …]`：本轮最关键的几件事 | 不显示 |
| `PREV` | `{title, note, rows: [[编号, 原来的提议, 怎么处理, 去向, 状态], …]}`：上一轮反馈的处理。第 5 列可选：`"open"`（或 `true`）表示这一轮还要定，去向高亮；`"done"` 表示已结束。不写第 5 列时，去向以 `R` 开头的算“还要定” | 不显示 |
| `OBJ` | `{id: {name, layer, lines, producer, editor, life, status, item}}`；`layer` 取 `goal` / `human` / `gate` / `agent` / `out`；`lines` 是几句短话的数组（对象视角里最多显示 4 句；泳道里全部显示，句子多了方框变高，一栏放得下的对象就少）；`item` 是相关卡片的编号。形状不对时 `__lint()` 报错，画不了的部分先不画（v3.7.1 起不会让整页出错）。讲结构的一轮必须写（见下文“沙盘”） | 没有“沙盘”和“对象”两节 |
| `NO_SANDBOX` | v3.7.1：字符串，一句话说明这一轮为什么不做沙盘（≤ 60 字；开头写了“这一轮没有沙盘”会去掉）。写成 `const NO_SANDBOX = "…";`。页面把“从零看懂”第 2 步换成“这一轮没有沙盘”和这句话，冷读材料里也有。只在没有 `OBJ` 时写，和 `OBJ` 一起写会报错 | 没有 `OBJ` 时第 2 步写“这一轮没有沙盘 · 这一页没有写为什么”，`__lint()` 提示（两张卡以上画了 `layers` / `flow` / `seq` 的图时点名这些卡） |
| `OBJ_LABELS` | `{name, layer, lines, producer, editor, life, status}` 里的任意几项：对象的字段名，同时用在对象表表头、对象视角和沙盘下方的说明里 | `名称`、`类别`、`是什么`、`谁产生`、`谁能改`、`状态变化`、`当前状态` |
| `FLOWS` | `[{id, name, desc, cols: [[id…], [id…], [id…]], links: [[from, to, 标签, 条目 id], …]}]`；最多三栏（两栏也行），栏里写 `OBJ` 的 id；连线只能从第 n 栏连到第 n+1 栏 | 没有流程视角 |
| `PANO_EDGES` | `[[from, to, 标签], …]`：全景里的连线，对象视角会用到 | 对象视角只用 `FLOWS` 的连线 |
| `viewAll()`、`SPOT_ALL` | 返回全景 SVG 的函数（可以用模板的 `defs`、`node`、`hTrack`、`wire`、`pill`、`COL`，签名见 references/svg-layout-and-visual-patterns.md）；全景下方的说明 HTML | 没有“全景”，沙盘从第一个流程（没有流程时从第一个对象）开始；既没有全景也没有流程时，左边的视角栏不显示 |
| `LAYER_NAME_X` | `{goal: …, human: …}`：改五个类别名 | 默认类别名 |
| `SRCB_X` | `{来源词: [样式, 标签]}`：增改分组卡里“点”的来源标签，样式取 `inf` / `cold` / 空，例如 `{"现行范式": ["cold", "现行范式"]}` | `推断`、`建议`、`冷读`、`你已定` 四种 |
| `TARGET_BASE` | `[落点, …]`：分组卡里要高亮（红色）的落点（`target`） | `["改基线"]` |
| `PAGE_TEXT` | `{元素 id: innerHTML}`；v3.4 的旧名 `SANDBOX_TEXT` 仍然有效 | — |
| `CODES` | 由 `codes.js` 提供；只在本页表格里出现的代号用 `Object.assign(CODES, {...})` 补 | — |
| `BRIEF` | v3.7 页面速览：`[[标签, 一句话, 样式], …]`，最多 6 行，每行 ≤ 80 字；样式写 `"hon"` 的一行用“实话”的颜色。常用四行：你要定 / 我的结论 / 实话 / 前提。有 `BRIEF` 时 cfg 的 `INTRO`、`LEAD` 收进“导语原文”折叠 | 显示原来的导语 |
| `GOALS` | v3.7：审批者自己定的目标，按优先级，`["① 做对", "② 少问你", …]`；分组卡的“目标让出图”按它排行 | 按点上出现的顺序 |

### 沙盘：什么时候做，最省事怎么写（v3.7.1）

一轮在讲“有哪些东西，谁产生、谁修改、谁能看到，怎么流动”时就做沙盘，在写卡片之前定下来。几个信号：两张卡以上要画同一批东西的 `layers` / `flow` / `seq` 图；有“谁能看 / 谁能改”这样的表；几个角色之间要交接；同一个议题的上一轮有沙盘。卡片上的图只画这张卡自己要定的那一块，全轮共用的结构在沙盘里画一次；一个视角能讲清一张卡的全部上下文时，那张卡用 `view` 连过去（按钮在卡头）。

最省事的沙盘不用算坐标：`OBJ` 给出对象表和每个对象的视角，对象视角里的连线来自 `FLOWS` 和 `PANO_EDGES`，所以至少写其中一个（一条连线都没有时，每个对象视角都写“没有上游 / 没有下游”，`__lint()` 会提示）。`FLOWS` 每条流程一张泳道图：最多三栏（上游 → 处理 → 下游，两栏也行），一个对象在一条流程里只出现一次，连线只能从第 n 栏连到第 n+1 栏；只要连线、不要泳道时写 `PANO_EDGES`（`[[从, 到, 标签], …]`）。要自己摆坐标的只有全景 `viewAll()`，可以不写，沙盘就从第一个流程开始。放得下的量：一栏最多 5 个对象（每个有 3–4 句时最多 4 个），连线标签最多 13 个字，每句最多 20 字左右；步骤的先后、往返（你 → 我 → 你）留给卡片上的 `seq` 图，参与的角色写进 `OBJ`。方框或标签跑出画布、标签的字比标签宽时 `test.js` 不通过。

```js
const OBJ = {
  you:  { name: "你", layer: "human", lines: ["提需求", "拍板"], producer: "—", editor: "—", life: "每轮", status: "已有" },
  me:   { name: "我（Claude）", layer: "agent", lines: ["写计划", "改代码"], producer: "—", editor: "—", life: "每轮", status: "已有" },
  repo: { name: "产品仓库", layer: "out", lines: ["代码和文档"], producer: "我", editor: "我改，你审", life: "每次发布更新", status: "已有" },
};
const FLOWS = [
  { id: "F1", name: "一次发布怎么走", desc: "从你提需求到仓库更新", cols: [["you"], ["me"], ["repo"]],
    links: [["you", "me", "提需求", "R04-01"], ["me", "repo", "改代码并提交", "R04-02"]] },
];
```

不做沙盘时写 `NO_SANDBOX`，例如 `const NO_SANDBOX = "只有三件小事：……，没有新的东西或流程要画。";`。既没有 `OBJ` 也没有 `NO_SANDBOX` 时，页面第 2 步写“这一轮没有沙盘 · 这一页没有写为什么”，`__lint()` 提示（不影响通过）。

### 条目（`ITEMS` 的每一项）

共有字段：`id`、`group`（分组标题）、`kind`、`title`、`from`（来源）、`weight`（`heavy` 需要细看 / `light` 可快速确认）、`mine`（可选，`true` / `false`：是不是“我的建议”；不写时看 `from` 里有没有“我的建议”，分组卡还看点的来源是不是 `推断` / `建议`）。

| `kind` | 卡片 | 专有字段 |
|---|---|---|
| `confirm` | 确认：✅ 通过 / 🤔 待微调 / ❌ 需修改 | `plain`；可选 `evidence`、`fig`（HTML 图）、`example`、`risk`、`view` |
| `choice` | 多选一：点一个选项就是表态 | `plain`、`opts: [[键, 标题, 说明, 是否推荐], …]` |
| `multi` | 可多选 | 同 `choice` |
| `group` | 分组决定卡：每一点单独表态 | `context`；可选 `example`、`risk`、`settled: […]`、`view`；`points: [{id, title, src, target, ifNo, why, risk, ex, text}]`，`id` 在卡内唯一（回答按它存），`src` 取 `你已定` / `推断` / `冷读` / `建议`（可用 `SRCB_X` 增改），`target` 在 `TARGET_BASE` 里时高亮 |
| `fill` | 填写：只有审批者知道的事实 | `plain`、`fields: [[字段 id, 标签, 占位提示], …]` |

`view` 是沙盘视图 id（`all`、`flow:F2`、`obj:XXX`），只在一个视图能讲清这一组的全部上下文时才给；视图不存在时不显示“在沙盘里看”按钮。v3.7.1 起按钮在卡头（“🗺️ 在沙盘里看全貌”，所有卡都一样），视图不存在时 `__lint()` 提示，不再悄悄不显示。

v3.7 起每种卡都可以再写 `brief`、`vis`、`tables`、`trust`、`needs`、`changed`，选项可以写成对象，分组卡可以写 `bulk: false`，点可以写成对照式。字段、形状和字数上限见下一节；怎么写见 `references/review-cards.md` 的 “Low Reading Load”。

其他约定：`OBJ` 的 `status` 含“待定”时方框画成虚线；一页里 SVG 的 `<marker id>` 必须唯一，同一张图用在几张卡上时给每张卡换后缀。

### v3.7 低负担字段

有 `brief` 的卡，默认只显示四格、最多两张图、依据可靠度和选项；`plain`（分组卡是 `context`）、`evidence`、`example`、`risk`、`settled`、`fig`、`tables`、收起的图原样收进“核对材料”，一个字都不改。所以会改变决定的风险不能只写在 `risk` 里，要写进 ③ 你会失去什么或 ⚖ 实话。没有 `brief` 的卡和 v3.6 一样画，只是也能带 `vis`、`tables`、`trust`（v3.7.1 起“在沙盘里看”按钮在卡头）。

字数上限都在模板的 `AD_LIMITS` 里（页面上 `window.__limits` 可以查），下面两张表照它写。字数按“字”算：中文字和全角标点算 1，英文字母、数字、半角标点和空格算 0.5。超了 `__lint()` 会引用原文报出来（算在字数预算里，见下文）。新字段有值就必须是文字；不能写 Markdown（页面不认 `**加粗**`，要写 `<b>…</b>`）；不带标签的文字里不能有换行符（页面上会变成空格，分行写 `<br>`）。

| 字段 | 形状 | 上限 |
|---|---|---|
| `brief` | `{ask, rec, cost, ifno, honest, lose, tag}`，不认识的字段报错。`ask` 必填；写了 `rec` 就要写 `cost`。每一格可以是字符串，或 `{t, basis, more}`：`basis` 取 `按文本数` / `实测` / `你已定` / `设计差异`（事实，实线框）或 `我的判断` / `估计` / `预期` / `推断`（判断，虚线框）；`more` 是这一格的全文，放在格子下的折叠里 | `ask` 40、`rec` 60、`cost` 60、`ifno` 60、`honest` 110 |

| `brief.lose` | ③ 里点名会失去的东西：`["名字", …]`；带出处时数组套数组：`[["拆解只对高风险任务做", "R03-05 第 4 点"], …]`。写了 `lose` 就要写 `cost`（失去的几项画在 ③ 那一格里）。以代号开头的字符串项报错：多半是把出处写成了单独一项 | 每项 18 |

`__lint()` 返回 `{errors, warnings, budget, mode, load}`。

- **errors**（一律不通过，`BUDGET: "warn"` 也不放过）：上面的形状、必填和不认识的字段；以及两条规则。一是**诚实**：每张 `versus` 都查，按审批者定的顺序（标 `"you"` 的段），第一条有 A / B 结论的那一行里，只要有一格偏向没推荐的选项（两边各有占优也算），就必须写 `brief.honest`。二是**数字出处**：默认看到的那一层（四格的正文、`tag`、`lose` 的名字、`trust`、显示的图、对象选项的 `d` / `short` / `up` / `cost` / `then` / `undo` / `fx` 的影响、对照式的点的 `area` / `from` / `to` / `sub` / `lose` / `no` / `labels` / `goal`）里两位以上的数，必须在本卡收起来的原文里找得到：`plain`、`context`、`evidence`、`example`、`risk`、`fig`、`settled`、参考表、点的说明（对照式的点连 `title` 也算）、选项的名字和原文（数组写法的选项连说明也算）、四格的 `more`。比之前先做全角转半角、去掉千分位逗号、去掉代号（`R03-05`、`DEC-5`、`v3.6` 这类带数字的标识），再按数值比（`3,889` 和 `3889` 算同一个数）；出处（`lose` 的第二项、图的 `ref`、`fx` 的卡片编号）不查。默认那一层有数、本卡却没有任何收起来的原文时，直接报错。一张卡的数据画不出来时，页面只把这一张画成出错卡（不会整页空白），`__lint()` 报出原因。v3.7.1 起还报：沙盘数据的形状不对（`OBJ` 的 `name`、`layer`、`lines`；`FLOWS` 的 id 重复、栏数、栏里的对象不在 `OBJ` 里或在一条流程里出现两次、连线的两端、标签和卡片编号；`PANO_EDGES` 的两端和标签），画不了的部分先不画；沙盘的第一个视角画不出来；`NO_SANDBOX` 和 `OBJ` 一起写；`NO_SANDBOX` 不是一句话；`view` 不是文字。
- **warnings**（只提示）：只有推荐的选项写了 `then` 或 `undo`（读起来像只有推荐的选项想清楚了）；`versus` 没有 `bands` 或没有标 `"you"` 的段（算不出第一条有结论的是哪条，诚实检查也就跳过了）。v3.7.1 起还提示：没有沙盘、也没写 `NO_SANDBOX`（两张卡以上画了 `layers` / `flow` / `seq` 的图时点名这些卡，数量在 `AD_LIMITS.sandbox.structural`）；沙盘一条连线都没有；`view` 写的视角在沙盘里没有。
- **budget**：字数超了。每张卡默认看到的字（中文字和英文单词各算一个，按钮、卡头芯片和固定的格名不算，图里的字另算）的预算：确认 / 选择 / 填写卡 `heavy` 700、不写 `weight` 480、`light` 300；分组卡 `heavy` 340 + 每点 80、不写 `weight` 280 + 每点 70、`light` 220 + 每点 60；显示的每张图里的字不超过 340 个；再加上面两张表里每一格的上限。预算让位于决定要用的事实：放不下时拆成两张卡，不要删，也不要把会改变决定的事实挪进折叠。cfg 的 `BUDGET: "warn"` 只把这几类检查降成提示：字数预算、读得清（字号、对比度）、375 / 360px 溢出，以及 v3.7.1 新加的沙盘画布检查（方框或标签跑出画布、标签的字比标签宽）；只用于重建以前的旧轮次。

卡头显示估读时间（每分钟 400 个字，图里的字按一半算），审批路线显示每张卡和整页的时间。

## 代号形状

`build_codes.py` 默认认四种形状：`D-009`、`FR-TASK-04`、`R03-07`、`M5` 这一类。项目有别的形状（例如 `GATE-01`、`DEC-1`、`ADR-0001`）时写一个 JSON，用 `--shapes` 传入：

```json
{"patterns": ["GATE-\\d{2}", "ADR-\\d{4}"], "kinds": [["^GATE-\\d{2}$", "关口"]], "only": false}
```

形状要写 Python 和 JavaScript 都认的正则（不要 `(?P<…>)`、内联标志、`\A`、`\Z`，也不能匹配空串），`build_codes.py` 会检查。用了 `--shapes` 时，`codes.js` 末尾会多一行 `CODE_SHAPES`，页面按同一套形状找出“像代号却没有解释”的字符串；不用时 `codes.js` 和 v1 完全一样，页面用默认形状。`--shapes` 只扩大“什么样的字符串算代号”，能识别的行格式仍是表格行、粗体标题、列表项和 `### R03-07` 反馈标题四种；写在别的格式里的代号，仍要靠项目自己的脚本生成代号表（把它的输出写进 cfg 的 `codes`），或在数据里 `Object.assign(CODES, …)`。`sample/code_shapes.json` 是一个例子。

## 从 v3.4 升级

| v3.4 的做法 | v3.6 起 |
|---|---|
| 把 round_template 和 `skill/` 子集复制进项目的 `build/`，在那里运行 `build.py` | 直接运行 `python3 <skill>/round_template/build.py cfg.json`，模板和公用模块取自 skill |
| 存储键 `{ROUND}-feedback-v1`、记住的文件夹 `reviews-dir` 不分项目（有的项目自己改过后两项） | cfg 必须写 `PROJECT`，三个键都带上它。升级前在本地答了一半、还没提交的轮次，重建后看不到之前的回答；已提交的不受影响；托管页面在新键为空时会从旧键接着读一次（每个 Artifact 的存储是独立的），所以原地重新发布也不丢 |
| 发布时声明 `capabilities: {db: {}}` | 声明 `capabilities: {db: {}, downloads: true}`（另存 md 要用）；草稿在 `drafts/{ROUND}`，不用另外声明 |
| 构建时按原文替换页面导语里写死的项目介绍句 | cfg 的 `INTRO`（原来 LEAD 里已经写了这句的，不用再写，页面上不会再出现两遍） |
| 替换 `expectedPathHint` 和 `interview/reviews` | cfg 的 `REVIEW_DIR`、`REVIEW_PATH_HINT` |
| 替换“访谈议程……”“访谈何时结束（……）”标题；cfg 的 `TCOND_TITLE`、`AGENDA_TITLE` | cfg 的 `AGENDA_TITLE`、`TCOND_TITLE`（同名，直接可用） |
| 替换议程下面的状态说明（本轮先定一部分 / 已定 / 后续轮次） | `PAGE_TEXT` 的 `agenda-legend` |
| 替换“从零看懂”的第 1、3 步；cfg 的 `HOWTO_1` | `PAGE_TEXT` 的 `howto-1`、`howto-3`（值里带上 `<b>1 先看这一节</b>` 这样的小标题） |
| 替换图例芯片；cfg 的 `LEGEND_CHIPS` | 默认按本页卡片类型生成；要改仍用 cfg 的 `LEGEND_CHIPS` |
| 替换图例后面那句话；cfg 的 `LEGEND_NOTE` | 默认句子只拿像编号的来源（如 `S-01`）举例；要改用 `PAGE_TEXT` 的 `legend`（整行，含芯片） |
| 替换对象表表头、对象视角和说明里的“当前状态”；cfg 的 `OBJ_STATUS_LABEL` | 数据里的 `OBJ_LABELS`，例如 `{status: "来自哪里"}`（三处一起改）；只想改表头才用 `PAGE_TEXT` 的 `obj-head` |
| 替换来源一节的说明；cfg 的 `SOURCES_LEAD` | `PAGE_TEXT` 的 `srcs-lead`（标题用 `srcs-title`） |
| 替换提交一节的说明 | `PAGE_TEXT` 的 `export-lead` |
| 替换分组卡里“需要你看的 n 点……” | `PAGE_TEXT` 的 `points-head`，`{n}` 是点数 |
| 把项目样式拼进 `</style>` | cfg 的 `CSS_FILE` / `CSS` |
| 正文里“概念说明”自动链接到来源（写死在模板里） | 数据里写 `SRC_AUTO = ["概念说明"]` |
| 分组卡里的自定义来源词只显示原文 | 数据里的 `SRCB_X` |
| 另写脚本补 `build_codes.py` 不认的代号形状 | 只是形状不同：`build_codes.py --shapes`；代号写在四种行格式之外：继续用项目的脚本，输出写进 cfg 的 `codes` |
| 反馈 md 头部的轮次行改成别的写法（如“提案发出：日期”） | 不支持：反馈 md 的格式固定，轮次行按“提案发出轮次 / 反馈对应轮次”写 |
| 悬浮摘要截前 140 字 | 取第一句（最多 140 字） |
| 评论框的元素 id 是 `c-<条目 id>`，和代号索引的 `c-<代号>` 重名 | 改为 `cm-<条目 id>`；项目脚本里按 `#c-…` 找评论框的要跟着改 |
| “一键通过”批量通过的确认 / 选择 / 多选条目没有任何标记 | 卡片上标“全页一键通过”，导出里写“状态：✅ 通过（全页一键通过）”，按推荐方案填入的选项也注明 |
| 反馈 md 里选择题的标题写成“〔 多选一〕” | 写成“〔多选一〕”（去掉多出的空格） |
| 输出 `{ROUND}_proposal.html` | `{ROUND}_{TOPIC}_proposal.html`；`test.js`、`dumptext.js` 给轮次号即可 |
| cfg 的 `N` | 不再需要 |
| 沙盘、议程、完成条件、关键几件事、来源都必须有 | 都可以省略 |
| 沙盘、对象、“从零看懂”第 1、3 步、整体意见提示的默认文字写的是“平台”“访谈”“议程顺序”和旧的按钮 | 默认文字改为中性写法；要原来的写法用 `PAGE_TEXT` |

没有变的：数据里 `KEY` 的写法（页面在前面加 `{PROJECT}/`）、数据库路径 `feedback/{ROUND}`、反馈文件名 `{ROUND}_{TOPIC}_feedback.md`、本地文件的两条导出路径（托管模式的变化见上）；数据里声明了 `PROPOSAL_FILE`、`TURN_PROPOSAL`、`TURN_FEEDBACK`，评审文件夹仍是 `interview/reviews` 时，反馈 md 的头部与 v3.4 逐字相同。

# Changelog

- **v3.7.1 (2026-11-19)**: The sandbox no longer disappears silently. Reason: the first two rounds built with v3.7 (project A R04, project B B1R1) had no sandbox, although they were about structure (two repositories, a seven-step sequence between four actors, a release chain, who can see or change what), and the reviewer asked whether the sandbox had been abandoned. Rebuilding the 7 real rounds with v3.6.1 and v3.7 showed the sandbox itself unchanged (same views, SVG, spotlight text, object table and card links in every view); what had changed was the guidance and the layout. (1) Rule: a round about structure (which things exist, who produces, changes or can see them, how they flow) gets a sandbox, decided before the cards; `OBJ` with `FLOWS` or `PANO_EDGES` needs no coordinates (only the panorama does, and it is optional); card pictures show one card's slice, and a card links to the sandbox with `view` when one view shows its whole context (SKILL.md principle 2, workflow step 1 and a hard rule; `references/page-and-export.md`, "When a Round Gets a Sandbox", with what fits in a column; `review-cards.md` points 3 and 6, L3 and L8; shapes and a minimal example in `round_template/README.md`). (2) `NO_SANDBOX`: a round without a sandbox gives a one-line reason. How-to step 2 is never removed any more: without a sandbox it reads "这一轮没有沙盘" with the reason, or "这一页没有写为什么", and a `PAGE_TEXT` `howto-2` no longer replaces it; sample R02 uses `NO_SANDBOX`. (3) Checks: a lint warning on every round with neither a sandbox nor `NO_SANDBOX`, naming the cards that use `layers` / `flow` / `seq` pictures when there are two or more (it fires on both rounds above); a warning for a sandbox with no links (every entity view would say 没有上游 / 没有下游) and for a `view` that names no existing view (the button used to vanish without a word); errors for `NO_SANDBOX` next to `OBJ`, an empty `NO_SANDBOX` and a non-string `view`. Because a sandbox is now expected more often and is written by hand, `OBJ` (name, one of the five layers, `lines` as an array), `FLOWS` (unique ids, one to three columns of known objects, each object once per flow, links from column n to n+1 with a label and an optional card id) and `PANO_EDGES` are checked: a mistake is a lint error and the part that cannot be drawn is left out, where before one string in `lines` stopped the whole page, cards included. `__check()` also fails boxes or labels outside the canvas (six objects in one column used to fall off it silently) and label text wider than its label (both only hint under `BUDGET: "warn"`, which is for rebuilding older rounds: project B R04's panorama has one 15-character label that touches its edge); a sandbox view that throws is reported and the rest of `test.js` still runs; a page whose script dies on load is reported with its error instead of `window.__views is not a function`. (4) Layout: the 审批路线 moved from STEP 0 to the top of STEP 3, right before the cards, so the how-to and the sandbox are back where they were in v3.6 (v3.7 had pushed the sandbox 660–1580px down at 1100px and 1100–2500px on phones, and moved the how-to step "看沙盘" off the first screen); "→ 下一个待表态" and "⚡ 先做可快速确认的" moved into the route's header, rows after the eighth fold under "其余 N 张卡" ("📖 展开全部说明" opens them too), and how-to step 3 points to the route unless the project overrides it; the "🗺️ 在沙盘里看全貌" button moved into the card head on every card and keeps the button look (on v3.7 brief cards it sat after the four boxes, the pictures and the 核对材料 row). (5) `dumptext.js` puts the sandbox into the cold read: pass 1 has its title, lead, views, the opening view and the object table (or step 2's text when there is none), pass 2 every view's spotlight and its links; hover texts now include codes from the sandbox, the object table and the route. The cold read also asks whether the sandbox covers the structure the cards rely on. Feedback Markdown is byte-identical to v3.7.

- **v3.7 (2026-11-19)**: Short visible layer per card. (1) Cards can carry four boxes (`brief`: ① 你在决定什么, ② 我推荐 and ③ 你会失去什么 side by side, ⚖ 实话, ④ 不同意会怎样; each sentence can be marked fact or judgment and carry its full paragraph in a fold); with a brief, `plain` / `context` / `evidence` / `example` / `risk` / `settled` / `fig`, reference tables and folded pictures fold unchanged into 核对材料. (2) Pictures drawn from data, at most two visible: `versus` (criterion comparison in the reviewer's priority order, with a computed "first criterion that separates them" line; side and strength spelled out for screen readers and on phones), `tree` (when the answer changes), `scale` (a threshold), `flow`, `seq` (sequence diagram; a numbered list on phones), `layers` (before/after structure), `bars` (quantities, assumption required); reference tables as data (`tables`, reflowing on phones); a reliability line (`trust`). (3) Options in object form with upside, cost, consequence, effects on other cards (`fx`: shown on the option, in the route and as a banner on the affected card once chosen) and the way back; the extras and the long description sit outside the clickable label, so reading them never selects the option. (4) Group points as diffs (`area`, `from` → `to`, `sub`, `lose`, `no`, `labels`, live `needs`, `goal`, `unsure`) with one 细节 fold per point on the answer row, a generated legend that states the majority source and target once, and a framed goal map with a text version (points without a stated goal are drawn hollow, not as "gives up nothing"); `bulk: false` removes "都同意" and makes the header one-click skip the group. (5) Page brief (`BRIEF`, the lead folds) and a generated 审批路线 (kind and count, weight, recommendation, honesty headline, prerequisites, option effects, minutes, status); reading times on every card and fold chip. (6) `window.__lint()` returns errors, warnings and budget overruns; every limit lives in one table (`AD_LIMITS`, also `window.__limits`). Errors: field shapes, required and unknown fields, option keys, Markdown or raw line breaks in the new fields, groups that mix diff and plain points, an honesty rule (every `versus` whose first separating criterion favours a non-recommended option — even in a split row — requires `honest`) and a number-source rule (numbers of two or more digits in the visible layer must appear in the card's folded prose; compared by value after NFKC, codes ignored). Warnings: only the recommended option has `then` / `undo`; a `versus` without a "you" band. A card whose data cannot be drawn becomes one error card instead of blanking the page, a failing export no longer stops answers from being saved, and keyboard focus survives re-rendering. `test.js` adds visible-text budgets, legibility (12px minimum, 4.5:1 contrast in light and dark), a neutral-recommendation check, 待你表态 on every open point, option extras that do not select, unique fold keys, `bulk: false`, export lines, and 375 / 360px widths; cfg `BUDGET: "warn"` turns only the budgets, legibility and the two widths into hints, for rebuilding old rounds. `dumptext.js` dumps two passes (default view, then everything) for a two-pass cold read. (7) Legibility fixes in the template: text and solid variants of the status colours (amber text on its tint was 2.5:1), an outlined "我的推荐" tag, no text under 12px in cards, long Latin strings wrap instead of widening cards on phones. Reason: project A R03 — every card had full context, but R03-02 showed about 3,900 characters before its options and the reviewer said the reading load and approval pressure were too high; four independent designs were mocked on that card and scored by three judges before this one was built, and the confirmed findings of an adversarial review of the first build were fixed before release. Measured on R03 with the same counting rule before and after: R03-02 3,867 → 691 visible characters (plus 361 in its two pictures); the whole page 8,292 → 3,894 (plus 561 in pictures), about 21 → 10 minutes at 400 characters a minute; the original text unchanged in folds. R03-05 shows about 30% fewer characters but is taller, because each point is drawn as two boxes. Exports of items that do not use the new fields are byte-identical to v3.6.1 (checked on seven real rounds).

- **v3.6 (2026-11-17)**: (1) Browser storage keys carry the project: cfg `PROJECT` is required and prefixes the answer key (`{PROJECT}/{ROUND}-feedback-v1`), the remembered-folder key and the folder-picker id. Reason: every local page shares one `file://` storage area, so another project's same-numbered round loaded these answers — a card the reviewer never touched showed as approved and went into the export. Unfinished local answers stored under the old keys are not carried over; hosted pages (each artifact has its own storage, so they never leaked) read the old key once when the new one is empty, so a round republished in place keeps its unfinished answers. (2) Hosted mode: answers are saved as a draft in `drafts/{ROUND}` 1.5 s after each change and continued on another device; drafts carry the storage key and a revision number, the page reads the draft before allowing answers, never overwrites a draft another tab or device saved meanwhile, ignores drafts saved under another key, stops drafting when the store refuses writes, and waits for the draft before submitting; the third export button saves a copy through the `downloads` capability (publish with `capabilities: {db: {}, downloads: true}`) and is hidden when that is unavailable; an unavailable database or failed write now says `没有提交成功` and selects the Markdown instead of pretending to download. Export module v4. (3) SKILL.md keeps the workflow and the hard rules; card design (`references/review-cards.md`), page modules, export and self-test details (`references/page-and-export.md`), the geometry rules (now in `references/svg-layout-and-visual-patterns.md`), the gotchas (`references/gotchas.md`) and this changelog moved out unchanged apart from the v3.6 updates. Reason: SKILL.md was read in full on every use (29.6 KB, 5 KB of it history). `test.js` also checks the key prefix and the hosted-mode behaviour.

- **v3.5 (2026-11-17)**: `round_template/` is the only template and moves to the skill root; it no longer contains text, paths or conventions from any project. Project specifics move to cfg (`INTRO`, `REVIEW_DIR`, `REVIEW_PATH_HINT`, `AGENDA_TITLE`, `TCOND_TITLE`, `LEGEND_CHIPS`, `PAGE_TEXT`, `CSS_FILE` / `CSS`) and data (`PAGE_TEXT`, `SRC_AUTO`, `OBJ_LABELS`, `SRCB_X`, `TARGET_BASE`, item `mine`, an open flag in `PREV` rows, the `points-head` text); the sandbox, agenda, completion conditions, key-change cards, sources and glossary are optional. `build.py` runs in the project's build folder against the skill's own template and modules (nothing is copied in) and writes `{ROUND}_{TOPIC}_proposal.html` / `_artifact.html`; `test.js` is generic and exits 1 on failure; `build_codes.py --shapes` adds project code shapes, which the code linker also uses (`CODE_SHAPES`); item tooltips take the first sentence. Unchanged: storage keys, the db path, the feedback file name and the export paths. The pre-v3.3 skeleton template and the five legacy builders moved to `archive/`. Versioning moved to git (tag `v3.4` is the last pre-git state; the `*.backup.*` files are gone), and an unrelated project folder moved out. Reason: every project had to string-patch the template's hard-coded wording and paths, and the old builders could no longer run. Upgrade notes: `round_template/README.md`. The "kept as `*.backup.*`" notes in the entries below now refer to files that exist only in git history (tag `v3.4`).

# Page Modules, Export and the Self-Test

Steps 1, 2 and 4 of SKILL.md before v3.6, moved here in full; the v3.6 changes (project prefix, hosted-mode drafts, `downloads`, honest failure), the v3.7 changes (page brief, route, four boxes, pictures, budgets, legibility) and the v3.7.1 changes (when a round gets a sandbox, `NO_SANDBOX`, the route moved to STEP 3, the sandbox button in the card head) are written into the text.

## Writing the Round as Data

The page is always built from `round_template/`, the only template. A round is a data file (`data_rXX.js`) plus a cfg (`cfg_rXX.json`); the full contract — every global, every cfg field and its default — is in `round_template/README.md`, and `round_template/sample/` has a first round that uses the sandbox, STEP 0 context, sources, glossary and all five card kinds (R01), and a sandbox-less second round with previous-round handling (R02).

- **Required**: `ROUND`, `TOPIC`, `ITEMS`. Everything else is optional; a module whose data is absent is not shown.
- **Reviewable Items (`ITEMS`)**: one card per decision, `kind` = `confirm` / `choice` / `multi` / `group` / `fill` (see `review-cards.md`), each with its origin in `from` (`我的建议` marks proposals of your own) and a `weight`. Since v3.7 a card can carry the four boxes (`brief`), pictures (`vis`), reference tables (`tables`), a reliability line (`trust`), prerequisites (`needs`), a change note (`changed`), options in object form, `bulk: false` (groups) and diff-style points; the page can carry `BRIEF` and `GOALS` (`review-cards.md`, "Low Reading Load").
- **Glossary (`TERMS`)**: term → [plain-language explanation, concrete example]; the first occurrence on each card is linked automatically.
- **Sandbox (`OBJ`, `FLOWS`, `PANO_EDGES`, `viewAll()`, `SPOT_ALL`)**: entities with layer, producer, modifier permissions, lifecycle and status; flows as upstream → processing → downstream columns; an optional hand-placed panorama. Required for a round about structure (next section); a round without one sets `NO_SANDBOX`.
- **STEP 0 context (`DELTAS`, `AGENDA`, `TCOND`, `PREV`) and sources (`SOURCES`, `SRC_AUTO`)**: optional.
- **Code Registry (`CODES`)**: `{ "D-009": ["标题", "说明", "类别 · 出处"] }`. Generate `codes.js` with `scripts/build_codes.py --out codes.js [--shapes code_shapes.json] <registry .md files…>` from the project's authoritative Markdown (decisions, open items, sources, spec, turn index, review index, previous feedback files — put the most authoritative file first; `--shapes` adds project code shapes such as `GATE-01`). In the round data, `Object.assign(CODES, {...})` every local label that only exists in this page's tables (e.g. `P1–P6`, `X1–X10`, sample-day labels). The page adds the round's `ITEMS`, `ROUND` and sandbox `FLOWS` itself.
- **Project specifics live in cfg and data, never in the template**: the project id (`PROJECT`, required: it prefixes the browser storage keys), the project's intro sentence (`INTRO`), the review folder (`REVIEW_DIR`), section titles and leads (`PAGE_TEXT`, `AGENDA_TITLE`, `TCOND_TITLE`), the legend (`LEGEND_CHIPS`), extra CSS (`CSS_FILE`). If a project needs something the template cannot express, extend the template upstream instead of string-patching a copy.

## When a Round Gets a Sandbox (v3.7.1)

Reason: the first two rounds built with v3.7 (project A R04, project B B1R1) had no sandbox, although they were about two repositories, a seven-step sequence between four actors, a release chain and who can see or change what. The reviewer asked whether the sandbox had been abandoned. It had not: the template still drew every view. But since v3.5 a round without `OBJ` hides the sandbox without a trace, v3.7's picture chooser sent structure to card pictures, and no rule said when a round needs a sandbox. Earlier (project B T15) the reviewer had asked for cards to link to a sandbox view whenever one view can show the whole context.

1. **Decide it before the cards.** If the round is about structure — which things exist, who produces, changes or can see them, and how they flow — it gets a sandbox. Signs: two or more cards would draw `layers`, `flow` or `seq` pictures of the same things; an access table (谁能看 / 谁能改); actors handing work to each other; the previous round of the same topic had a sandbox.
2. **The cheapest sandbox needs no coordinates.** `OBJ` gives the object table (谁产生 / 谁能改 / 状态变化) and one view per entity; the entity views draw the links from `FLOWS` and `PANO_EDGES`, so give at least one of them (without links every entity view says 没有上游 / 没有下游, and the lint warns). `FLOWS` adds one swimlane per flow: up to three columns (upstream → processing → downstream; two also work), each object once per flow, links only from column n to n+1. `PANO_EDGES` (`[[from, to, 标签], …]`) adds links without a swimlane. Only the hand-placed panorama (`viewAll()`, `SPOT_ALL`) needs coordinates, and it is optional; without it the sandbox opens on the first flow. What fits: at most 5 objects per column (4 when they have 3–4 lines), link labels up to 13 characters, lines up to about 20 characters; an order of steps or a round trip (你 → 我 → 你) stays in the card's `seq` picture while its actors go into `OBJ`. `test.js` fails a box or label that leaves the canvas or a label whose text is wider than the label. A shape mistake in `OBJ`, `FLOWS` or `PANO_EDGES` is a lint error; the part that cannot be drawn is left out instead of breaking the page. Shapes and an example: `round_template/README.md`, “沙盘”.
3. **Cards keep their own slice.** A card picture shows what this card decides (the two options' structures, the steps after a choice). The structure the whole round shares lives in the sandbox once, and a card links to it with `view` when one view shows the card's whole context (`review-cards.md`, point 3). The link is the "🗺️ 在沙盘里看全貌" button in the card head.
4. **No sandbox? Say why.** Set `const NO_SANDBOX = "…";` to one line (≤ 60 characters, e.g. “只有三件小事：……，没有新的东西或流程要画。”; a leading “这一轮没有沙盘” is dropped). The page shows it as how-to step 2 ("2 这一轮没有沙盘"), and the cold-read dump includes it. Without `OBJ` and without `NO_SANDBOX`, step 2 reads "这一轮没有沙盘 · 这一页没有写为什么", and `__lint()` warns, naming the cards that use `layers`, `flow` or `seq` pictures when there are two or more. A `howto-2` in `PAGE_TEXT` is ignored on a round without a sandbox.

## Building the Page

In the folder that holds the cfg and data, run `python3 <skill>/round_template/build.py cfg_rXX.json`. It fills the template, inlines `codes.js`, the data, `assets/code-linker.js` and `assets/export-module.js`, and writes `{ROUND}_{TOPIC}_proposal.html` (complete document, the local copy) and `{ROUND}_{TOPIC}_artifact.html` (the same page without doctype/html/head/body, for the Artifact tool). The template provides six modules; the data decides which of them appear:

1. **Sticky top navigation**: round badge, section pills, live progress (`已表态 X / N`), `✅ 一键通过未填项（按推荐方案）` and `📤 提交反馈（导出 md）`.
2. **STEP 0 · 从零看懂**: the page brief (`BRIEF`, v3.7; the lead `INTRO` + `LEAD` is then folded as 导语原文, otherwise it shows as before), a five-step how-to (step 2 "看沙盘"; without a sandbox it reads "这一轮没有沙盘" plus the `NO_SANDBOX` reason, or "这一页没有写为什么"; step 3 points to the route when the route is shown, unless the project overrides `howto-3` in `PAGE_TEXT`), optional agenda, completion conditions and previous-round handling, clickable key-change cards (`DELTAS`) that jump to their items, and a legend of the card kinds used on the page. Since v3.7.1 nothing new sits between the lead and the how-to, so the how-to and the sandbox are where they were in v3.6.
3. **STEP 1 · 沙盘** (only with `OBJ`): panorama (`viewAll`), one 3-column swimlane per flow, one ego view per entity, and a spotlight panel under the canvas that explains the active view with jump buttons to related items.
4. **STEP 2 · 对象** (only with `OBJ`): the entity table; clicking a row focuses that entity in the sandbox.
5. **STEP 3 · 逐条表态**: the 审批路线 first (v3.7, at the top of STEP 3 since v3.7.1; generated: one row per card with kind and count, weight, recommendation, the first clause of `honest`, prerequisites and option effects, reading minutes and status; "→ 下一个待表态" and "⚡ 先做可快速确认的" sit in its header; rows after the eighth fold under "其余 N 张卡", which "📖 展开全部说明" also opens; off with cfg `ROUTE: false`), then filter pills (`📋 全部条目`, `🗳️ 需要选方案的`, `✨ 含我的建议`, `⏳ 尚未表态`, `📖 展开全部说明`), the sticky table of contents with status dots, the cards, and an overall-comment box. Each card head shows its reading time (v3.7) and, when the card's `view` exists, the "🗺️ 在沙盘里看全貌" button (v3.7.1; before, it sat in the card body: after the four boxes, pictures and fold chips on brief cards, after the example and risk folds on other cards). A card with a `brief` shows the four boxes, at most two pictures, the reliability line, a 核对材料 row of fold chips (each with its reading time) and the options; a group with diff-style points shows a generated legend, the goal map and one "现在 → 改成" row per point. When an option with `fx` is chosen, the affected cards show a banner (it never answers for the reviewer).
6. **STEP 4 · 附录 and STEP 5 · 提交**: the code index (`#code-index`, every code used on the page, anchored as `#c-<code>`), glossary and sources; live summary counters, a read-only preview of the Markdown report, a copy button, the `#save-target` status line and the export buttons. **Markdown only — never export or offer JSON (v3).** Since v3.7 an item that uses the new fields gets extra lines in its section (`上轮之后改了`, `前提`, `简报` with the five boxes and the named losses, `依据可靠度`, `图` with a text form of every picture, `参考表` as Markdown tables, one line per object-form option with 好处 / 代价 / 选了之后 / 影响 / 选错了怎么退 / 原文, and `批量` for `bulk: false`); an item without them exports exactly as in v3.6.

Export (`assets/export-module.js`, inlined by the build) tries three paths in order:
  1. **Hosted mode (default, guarantees the file lands in the review folder)**: publish `{ROUND}_{TOPIC}_artifact.html` as a claude.ai Artifact with `capabilities: {db: {}, downloads: true}`. `提交反馈` writes `{round, topic, proposal, filename, submitted_at, md}` to the artifact database doc `feedback/{ROUND}`. When the user says “反馈完成”, read it with `ArtifactData get collection=feedback doc_id={ROUND}` and write `md` to `{REVIEW_DIR}/{ROUND}_{TOPIC}_feedback.md` yourself (device shell / file tools). Browser file APIs and plain downloads are blocked inside the artifact viewer, so never rely on them there. Since v3.6 the hosted page also:
     - keeps a draft in `drafts/{ROUND}` (`{round, topic, key, rev, saved_at, answered, md, state}`). On load it reads the draft first (the answer controls are inert for those moments) and continues from it when the draft's key equals the page's storage key and its revision `rev` is higher than the one the browser's copy is based on; after that it saves 1.5 s after each answer, re-reading first and refusing to overwrite a draft that another tab or device saved meanwhile (it asks to reload instead). Ordering uses `rev`, never device clocks. A failed read (after one retry) turns drafts off for that visit; a write the store refuses (typically a view-only reviewer) turns drafts off and says that submitting will not work either. A pending draft is flushed when the tab is hidden. So the reviewer can switch devices, and `ArtifactData get collection=drafts doc_id={ROUND}` shows you their progress and the partial Markdown;
     - turns the third button into `💾 另存一份 md 到本机`, which saves through the `downloads` capability after the viewer confirms, and hides it when `downloads` is unavailable;
     - says `没有提交成功` and selects the Markdown preview for copying when the database is unavailable (not declared, signed out) or the write fails, instead of falling back to a download that the viewer blocks; a submit made while the draft is still loading waits for it and, if a newer draft replaced the answers, asks the reviewer to check before submitting; repeated clicks submit once, and a transient `unavailable` is retried once;
     - reads the pre-v3.6 unprefixed storage key once when the new key is empty, so a round republished in place keeps the reviewer's unfinished answers (safe because each artifact has its own storage; local files never do this).
  2. **Local file + Chrome/Edge**: File System Access API writes the `.md` into the remembered review folder (picked once, handle kept in IndexedDB under `{PROJECT}/reviews-dir`).
  3. **Fallback**: copy the Markdown to the clipboard and download one `.md`.

Keep the local copy at `{REVIEW_DIR}/{ROUND}_{TOPIC}_proposal.html` and the artifact build in `{REVIEW_DIR}/artifact/`; record the artifact URL in `{REVIEW_DIR}/INDEX.md`. `REVIEW_DIR` is the cfg field of that name (default `interview/reviews`).

## Verifying Before Delivery

1. In the build folder run `NODE_PATH=<node_modules with playwright> node <skill>/round_template/test.js {ROUND}`. It must end with `✓ 全部通过` (exit code 0). Since v3.7 it also prints each card's visible text, budget and reading time, and checks: `window.__lint()` (field shapes and limits, the honesty rule for every `versus`, the number-source rule; its warnings are printed but do not fail), the budgets, legibility (no text under 12px and contrast of at least 4.5:1 in the item area, page brief and route, in light and dark, with all folds open), that the recommended option is styled like the others and its tag has no fill, that every undecided point shows 待你表态, that clicking an option's extras or its 原文 chip does not select the option, that no two fold chips share a key, that one-click skips `bulk: false` groups, that items with a brief or pictures have them in the export, and no overflow of cards, pictures or tables at 375px and 360px with all folds open (cfg `BUDGET: "warn"` turns only the budgets, legibility, the two widths and, since v3.7.1, the two sandbox canvas checks into warnings; lint errors still fail). It checks: 0 overlaps and 0 out-of-box texts in every sandbox view (`window.__check()`: label-node, label-label, line-through-node, line-through-label, text overflow); since v3.7.1, that every sandbox view can be drawn and keeps its boxes and labels on the canvas with label text that fits, that the route sits at the top of STEP 3, before the cards, and that a round without a sandbox says so in how-to step 2 with the `NO_SANDBOX` reason when there is one (the "沙盘：" line prints what step 2 shows); the lint also errors on sandbox data of the wrong shape (`OBJ`, `FLOWS`, `PANO_EDGES`), on `NO_SANDBOX` next to `OBJ` or empty, and on a `view` that is not a string, and warns about a round with neither a sandbox nor a reason, about a sandbox with no links, and about a `view` that names no existing view; no unknown codes (`window.__unknownCodes` empty) and every code on the page (`.code[data-c]`: a link, or a span inside an option label or button) has a matching `#code-index .ci`; the storage key starts with `{PROJECT}/`; hosted mode with a mocked `window.claude.use` (a draft reaches `drafts/{ROUND}` after an answer, `提交反馈` writes `feedback/{ROUND}` with `md`, the save-a-copy button goes through `downloads`, a newer draft in the database is continued on load, and an unavailable database gives `没有提交成功` with no download); mocked `showDirectoryPicker` gets exactly one `.md`; without both, exactly one download; no duplicate element ids; bulk-approved items labelled "全页一键通过" on the card and in the export; no horizontal overflow at 400px; 0 page errors. Fix code gaps by adding entries to `CODES`, never by rewording the page to hide the code.
2. Run the two-pass approver cold read (`review-cards.md`, point 6) and revise until no card blocks a decision and the second pass changes nothing.
3. If replacing an existing proposal file in a review folder, back up the original file to `<filename>.backup.html` first.
4. After publishing the artifact: `ArtifactData list feedback` once (and optionally one probe write + delete) to confirm the store works; give the user the artifact card, not a local file link, as the place to review.

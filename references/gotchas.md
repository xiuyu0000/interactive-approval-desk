# Gotchas

Pitfalls met in earlier rounds, moved here from SKILL.md in v3.6 without changes, except where noted (v3.6).

- **Midpoint Label Pile-Ups**: Never place edge labels at naive `(x1+x2)/2, (y1+y2)/2` midpoints across a multi-column grid. Multiple diagonal edges will converge on the canvas center and cover middle column cards. Always use dedicated corridors and sorted vertical slots.
- **Defaults Look Like Answers (v3.4)**: v3.3 pre-set every group point to "同意". After an interruption the reviewer could not tell which 同意 they had given and which were defaults. Never initialise a point or item with an answer; a stored point state is `{v: null, c: "", how: null}` until clicked. Pages built before v3.4 that stored `v: "yes"` without `how` are read as explicit answers. (v3.6.1) The same now holds for confirm / choice / multi items: the page-wide bulk button stores `how: "all"` (and `howRec` when it filled in the recommended option), the card shows "全页一键通过", and the export says so; any click on the card's own controls clears it.
- **Unselected Choice on Approval**: a `choice` card is answered by clicking an option. When the page-wide bulk button approves a `choice` or `multi` item that has no selection (or `✅ 通过` is clicked on a `multi` item with nothing ticked), the template fills in the recommended option(s) (`opts[i][3] === true`) so the exported report never has an approved decision with `choice: null`; items without a recommendation are skipped and named in the toast.
- **Breaking Downstream Automation Keys**: In multi-round workflows (like `R01`, `R02`), preserve the exact `localStorage` key pattern (`{PROJECT}/{ROUND}-feedback-v1` since v3.6; `{ROUND}-feedback-v1` before), the feedback file name `{ROUND}_{TOPIC}_feedback.md`, and the db doc paths `feedback/{ROUND}` and `drafts/{ROUND}`.
- **Answers Leaking Between Projects (v3.6)**: every page opened from a local file shares one browser storage area (`file://`). Before v3.6 the key had no project in it, so opening another project's local `R03` page loaded this project's `R03` answers into cards with the same ids — they showed as answered and went into the export. `cfg.PROJECT` is now required and prefixes the answer key, the remembered-folder key and the folder-picker id. Hosted pages were never affected (each artifact has its own storage).
- **Static Tooltip Overflow on Screen Edges**: Use a single fixed `#tip` positioned via `mousemove` with viewport boundary clamping (`clientX + 14`, flipping left/up near window edges) rather than pure CSS `:hover::after` pseudo-elements that get clipped by `overflow: hidden` containers.
- **Export Silently Failing (v2 partial fix, v3 real fix)**: a page opened from a local file can still fail to write when it runs inside an app preview pane or a browser without the File System Access API — v3 therefore publishes the desk as an Artifact and stores feedback in its db, and the agent writes the file. Earlier causes: (1) File pickers are blocked inside cross-origin iframes such as an app's preview pane — detect `window.self !== window.top` and explain; (2) browsers block a second programmatic download fired right after the first, so the old "download .md then .json" fallback lost the JSON — use a single combined file; (3) Safari/Firefox have no `showDirectoryPicker`; (4) binding `exportBtn.onclick = triggerFullExport` passes the click event as the first argument — always wrap: `() => triggerFullExport(false)`. (v3.6) In the hosted viewer the old fallback still pretended success: with the database unavailable it "downloaded" a file the viewer blocks and said so. The module now says `没有提交成功` and selects the Markdown for copying, and saves copies only through the `downloads` capability.
- **Same Figure in Several Cards**: an item figure reused by more than one card duplicates its SVG `<marker id>`s, and a marker defined inside a hidden card may not render elsewhere. The template inserts `it.fig` as given, so give each card's copy its own marker ids — e.g. generate the figure HTML per item with the item id as a suffix.
- **Stale Text When Chaining Rounds**: when a round's data and cfg start as a copy of the previous round's, `LEAD`, `DELTAS`, `PAGE_TEXT` and item texts still carry the old round's IDs, dates and topics. Before publishing, grep the new data, cfg and built page for the previous round's IDs, dates and topics.
- **Bare Codes Without Explanation (v3.2)**: earlier rounds showed `M5`, `D-014 N1`, `R03-07` as plain text, so the reviewer could not tell what they meant. Every code must go through `adLinkCodes`. Watch for codes inside figure tables, option descriptions, the "上一轮反馈处理" table, spotlight text and the item "来源" line — all are covered only if their container is passed to `adLinkCodes` after rendering. Codes inside SVG labels are not linked; keep SVG labels code-free or explain the code in the spotlight panel.
- **Default Save Path**: Browsers cannot write to a hard-coded absolute path. Achieve a default review folder (`REVIEW_DIR`) by remembering the directory handle after the first pick (IndexedDB) and showing the remembered target in `#save-target`.

## Walls of Text (v3.7)

**Symptom**: every card is "complete" but the reviewer has to read 600–4,000 characters per decision; the page takes 20+ minutes and the catch of a recommendation sits in the fifth paragraph. **Cause**: principle 6 (full context on the card) met a template that only had paragraph slots, so context was written as prose. **Fix**: the four boxes, pictures drawn from data and folds (`review-cards.md`, "Low Reading Load"); `test.js` fails a card over its visible budget. **Do not** meet the budget by deleting the record or by rewording an admission into something softer: move prose into folds, keep the honesty sentence as plain as in the prose, and keep every number's assumption beside it.

## One-Sided Pictures (v3.7)

**Symptom**: a bar chart "73 → 30" next to 我推荐, with the assumption ("if you agree to R03-05 points 1–7") only in a fold; a comparison grid placed first on a card that argues for the recommendation. **Fix**: show both options in every picture; put the counting rule and assumption in `cap` (required for `bars`); the number-source lint catches numbers with no source in the folded prose. Pictures are evidence, never persuasion.

## Silent Sandbox Loss (v3.7.1)

**Symptom**: the first two rounds built with v3.7 (project A R04, project B B1R1) had no sandbox, although they were about two repositories, a seven-step sequence between four actors, a release chain and who can see or change what; each card drew its own slice as `layers` / `flow` / `seq` instead. The reviewer asked whether the sandbox had been abandoned. **Cause**: since v3.5 a round without `OBJ` hides the sandbox without leaving a trace on the page; v3.7's picture chooser sent structure to card pictures, workflow step 1 named only the card fields, and no rule said when a round needs a sandbox; the v3.7 route sat above the how-to and pushed the sandbox 660–1580px further down. **Fix**: a round about structure gets a sandbox, decided before the cards (`page-and-export.md`, "When a Round Gets a Sandbox"); `OBJ` with `FLOWS` or `PANO_EDGES` needs no coordinates; a round without one says why in `NO_SANDBOX`, shown as how-to step 2, and the page says "这一轮没有沙盘" even when the reason is missing; the lint warns on every round with neither and names the cards that draw structure pictures; the route moved to the top of STEP 3. **Do not** replace the sandbox with the same structure drawn card by card.
